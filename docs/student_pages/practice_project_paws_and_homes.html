Paws & Homes

A pet adoption app. People browse pets waiting for a home, open a pet's profile, and fill in an adoption form. You will build it from scratch using only what we have covered so far: Dart, widgets, layouts, theming, navigation and forms.

What you hand in

A GitHub repository with the working app, a README with screenshots of all four screens, and at least 5 commits.

What the app does

  • The home screen loads a list of pets (with a loading spinner) and shows them in a scrolling list.
  • A row of category chips at the top filters the list: All, Dogs, Cats, Birds.
  • Each pet card has a heart button to mark it as a favourite.
  • Tapping a pet opens its profile with a large photo, three stat tiles and an Adopt me button.
  • The adoption form checks every field before it can be submitted.
  • After submitting, the pet shows an Adopted badge and a SnackBar confirms it.
  • An icon in the home AppBar opens My applications, a list of everything you've applied for.

Rules you must follow

  1. Use named routes only. Put every route name in an AppRoutes class as constants. Don't use MaterialPageRoute anywhere. Pass data with arguments.
  2. Take every color and font from the theme. Define them once in lib/theme.dart and read them with Theme.of(context). No Colors.xxx or Color(0x…) in screens or widgets.
  3. Use a custom font from assets/fonts/ and at least 6 pet images from assets/images/, both registered in pubspec.yaml.
  4. Build lists with builders. Use ListView.builder or GridView.builder for every list of pets or applications.
  5. Validate every form field with the rules in the table below, and submit only when validate() returns true.
  6. Dispose every TextEditingController in dispose().
  7. Check mounted after every await before using context or calling setState.
  8. No overflow errors. The app must run without yellow-and-black stripes on a small phone (360 px wide), including with the keyboard open on the form.
  9. No extra packages. Only flutter itself. Riverpod, http and Firebase come in later sessions.
  10. Commit as you go. At least 5 commits with clear messages (for example “Add pet list screen”), pushed to GitHub.

Data model

Start with these classes in lib/models/. You can add fields, but don't remove any.

abstract class Pet {
  Pet({
    required this.id,
    required this.name,
    required this.breed,
    required this.ageInYears,
    required this.gender,
    required this.weightKg,
    required this.imagePath,
    required this.description,
    this.isVaccinated = false,
    this.isNew = false,
  });

  final String id;
  final String name;
  final String breed;
  final int ageInYears;
  final String gender;
  final double weightKg;
  final String imagePath;
  final String description;
  final bool isVaccinated;
  final bool isNew;

  String? adoptedBy;                         // null until someone adopts
  bool get isAdopted => adoptedBy != null;

  String get type;                           // 'Dog', 'Cat' or 'Bird'
  String careTip();                          // each subclass overrides this
}
